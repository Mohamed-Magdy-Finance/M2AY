# M2AY — موقع محمد مجدي المالي

موقع دليل مالي احترافي (26 فصل)، قوالب Excel، وبنك أسئلة مقابلات (160+ سؤال)، مبني بـ React + Express + PostgreSQL.

---

## 🚀 النشر المجاني (خطوة بخطوة) — مرة واحدة بس

الخطوات دي هتاخد حوالي 15-20 دقيقة، وبعدها الموقع هيفضل شغال مجانًا للأبد.

### 1) قاعدة البيانات (Neon — مجاني للأبد)

1. روح على [neon.tech](https://neon.tech) واعمل حساب مجاني (تقدر تسجل بحساب GitHub بتاعك مباشرة)
2. اعمل "New Project" (اختار أي اسم، وأي منطقة قريبة منك)
3. هيديك رابط اسمه **Connection String** شكله زي:
   `postgresql://user:password@ep-xxxx.neon.tech/dbname?sslmode=require`
4. احتفظ بالرابط ده، هتحتاجه في خطوة 3

### 2) ارفع الكود على GitHub

1. اعمل حساب على [github.com](https://github.com) لو مش عندك
2. اعمل Repository جديد (اسمه مثلاً `m2ay-website`)
3. ارفع كل الملفات دي عليه (تقدر تستخدم GitHub Desktop أو الأوامر دي من جهازك):
   ```bash
   git init
   git add .
   git commit -m "M2AY website"
   git branch -M main
   git remote add origin https://github.com/USERNAME/m2ay-website.git
   git push -u origin main
   ```

### 3) الاستضافة (Back4app Containers — مجاني تمامًا، بدون كارت بنكي)

> **ملاحظة:** جربنا Render الأول، لكنه بيطلب كارت بنكي في بعض المناطق حتى للخطة المجانية. Back4app بديل حقيقي مجاني 100% ومتأكد إنه مش محتاج كارت خالص. المشروع فيه ملف `Dockerfile` جاهز عشانه بالظبط.

1. روح على [back4app.com/containers](https://www.back4app.com/) واعمل حساب (سجّل دخول بحساب GitHub مباشرة — مفيش كارت مطلوب)
2. اختار "Containers" / "Web Deployment" من الداشبورد
3. اربط حساب GitHub بتاعك واختار الـ Repository اللي رفعته
4. Back4app هيكتشف ملف `Dockerfile` الموجود في المشروع تلقائيًا ويستخدمه للبناء
5. تحت "Environment Variables" ضيف نفس المتغيرات دي:
   | الاسم | القيمة |
   |---|---|
   | `DATABASE_URL` | رابط Neon من خطوة 1 |
   | `JWT_SECRET` | أي نص عشوائي طويل (مثلاً 40 حرف عشوائي) |
   | `ADMIN_EMAIL` | mohamedeones123@gmail.com |
   | `ADMIN_PASSWORD` | M*01000# |
   | `NODE_ENV` | production |
   | `PORT` | 3000 |
6. اضغط Deploy، واستنى شوية لحد ما يخلص البناء

**لو حصلت لاحقًا على كارت بنكي وحبيت Render:** الخطوات هتكون شبه مطابقة (Build Command: `npm install && npm run build`, Start Command: `npm start`)، والمشروع شغال بنفس الكفاءة على الاتنين.

### 4) زرع البيانات (مرة واحدة فقط)

بعد ما الموقع يشتغل، شغّل أمر الزرع مرة واحدة من جهازك (لازم يكون `DATABASE_URL` بتاعك متسجل في ملف `.env` عندك محليًا):

```bash
npm install
cp .env.example .env
# افتح .env وحط فيه رابط Neon الحقيقي
npm run db:seed
```

ده هيملى قاعدة البيانات بـ: حساب الأدمن، بياناتك الشخصية، الـ26 فصل، الـ12 قالب، وبنك الأسئلة كامل.

### 5) خلاص!

الموقع بقى شغال على رابط بصيغة زي `m2ay-website.back4app.io` (أو الدومين اللي هيديهولك)، ومتاح لأي حد يفتحه، بـ HTTPS تلقائي، ومجاني بالكامل.

**ملاحظة عن الخطة المجانية:** الموقع ممكن "ينام" بعد فترة من عدم الاستخدام (الخطة المجانية بتديك 600 ساعة تشغيل شهريًا)، وياخد شوية ثواني يصحى تاني أول ما حد يفتحه — ده طبيعي في أي خطة مجانية ومقبول تمامًا لموقع شخصي.

## ✅ إضافات هذا التحديث (Sprint الأول)

- **SEO:** meta tags ديناميكية لكل صفحة (title, description, canonical, Open Graph, Twitter Card)، JSON-LD Schema لصفحات الفصول، sitemap.xml ديناميكي (بيعكس الفصول والقوالب الحقيقية تلقائيًا)، robots.txt
- **صفحتا سياسة الخصوصية وشروط الاستخدام:** `/privacy-policy` و `/terms-of-use`، مرتبطتين في الفوتر
- **Draft/Publish للفصول:** كل فصل له حالة (مسودة/منشور) قابلة للتبديل من الأدمن؛ الفصول في وضع "مسودة" لا تظهر للزوار خالص
- **تحسين الأداء:** الصورة الشخصية اتضغطت من 784 كيلوبايت لـ127 كيلوبايت (نفس الجودة)، مع `fetchPriority` و `loading="lazy"` مضبوطين حسب موقع كل صورة

## ✅ إضافات هذا التحديث (تعميق Sprint الأول)

- **SEO حقيقي من السيرفر:** meta tags، OG، Twitter Cards، Canonical، hreflang، وJSON-LD بنوع Schema مختلف لكل نوع محتوى (Article للفصول، CreativeWork للقوالب، FAQPage لبنك الأسئلة، Person + ProfessionalService لصفحة "من أنا") — بتتحقن من السيرفر مباشرة في HTML (مش بس عبر JavaScript)، فمحركات البحث تقدر تقرأها فورًا
- **إصلاح باج اللغة:** صفحة الفصل بقت تحترم زرار اللغة فعليًا، ولو مفيش محتوى إنجليزي بيظهر تنويه واضح بدل ما يترجع عربي بصمت
- **الأدمن مقسّم Tabs:** محرر الفصل بقى فيه 5 تبويبات (عام، المحتوى، الخاتمة، SEO، الربط) بدل صفحة واحدة طويلة، وكل حقول الفصل (بما فيها الخاتمة الكاملة و SEO) بقت متاحة للتعديل
- **SEO فردي لكل فصل/قالب:** حقول اختيارية (SEO Title, Description, Keywords, OG Image, Slug) — لو سبتها فاضية، النظام يولّد قيم تلقائية من العنوان والخلاصة
- **Related Content:** تحت كل فصل بقى يظهر تلقائيًا: القوالب المرتبطة، فئات أسئلة المقابلات المرتبطة، وأزرار "الفصل السابق/التالي"
- **Preview تلقائي مجاني للقوالب:** بانر SVG/CSS مولّد بالكود (بدون أي ذكاء اصطناعي أو تكلفة) للقوالب اللي مفيهاش صورة مرفوعة — بلون وأيقونة حسب التصنيف، مستوى الصعوبة، وتاريخ آخر تحديث
- **Config-Driven:** اسم الموقع ونص الفوتر بقوا قابلين للتعديل من الأدمن (تبويب الإعدادات) بدل ما يكونوا مكتوبين في الكود

## ✅ إضافات هذا التحديث (فصل اللغة في روابط + تحسينات UX/SEO)

- **فصل اللغة في روابط منفصلة تمامًا:** كل صفحة بقى ليها رابط عربي (`/ar/...`) ورابط إنجليزي (`/en/...`) حقيقي ومستقل، بدل التبديل بـ state داخل نفس الصفحة. ده بيخلي الـ hreflang يشتغل بأقصى فايدة SEO ممكنة، وجوجل يقدر يفهرس النسختين بشكل منفصل وصحيح.
- **Breadcrumbs:** ظاهرة دلوقتي في صفحات تفاصيل الفصل والقالب وفئة بنك الأسئلة (الرئيسية > القسم > العنصر)، مع BreadcrumbList Schema لتحسين الظهور في نتائج البحث.
- **بطاقة الفصل أغنى:** بقى فيها وصف مختصر (لو موجود) وعدد القوالب المرتبطة بيه، بدل بس العنوان والرقم.
- **إصلاح باج تقني مهم اكتشفته أثناء الاختبار الفعلي:** كان فيه سلوك معروف في Express بيخلي `req.path` يرجع دايمًا "/" جوه route من نوع `"*"` (بدل المسار الحقيقي)، وده كان معناه إن كل صفحات الموقع هتاخد نفس الـ meta tags بغض النظر عن اللغة أو الصفحة، رغم إن الكود شكله سليم. اكتشفته باختبار فعلي للسيرفر شغال (مش بس فحص كود)، واستخدمت `req.originalUrl` بدل منه. اتأكدت بعد الإصلاح إن كل صفحة فعليًا بترجع الـ meta والـ JSON-LD الصح بلغتها.

## ✅ Sprint 1 الكامل (أمان + إدارة محتوى احترافية)

### 🔒 الأمان
- **Rate Limiting** على تسجيل الدخول (5 محاولات كل 15 دقيقة لكل IP) — اتفحص فعليًا وشغال
- **Security Headers** (Helmet): Content-Security-Policy، X-Frame-Options، X-Content-Type-Options
- **Cookie hardening:** httpOnly + SameSite=Lax + Secure (بدل الإعداد القديم الأقل أمانًا)
- **drizzle-orm** اتحدّث لأحدث نسخة (فيها إصلاح ثغرة SQL injection كانت في النسخة القديمة)

### ✍️ محرر أقوى
- **Markdown Editor** لمحتوى الفصول (Bold/عناوين/قوائم/روابط + معاينة حية) — بدل Textarea عادي
- **عرض المحتوى بقى Markdown حقيقي** في صفحة الفصل (مش نص خام) — تحسين تلقائي حتى للمحتوى الموجود
- **Auto Save** كل 2.5 ثانية بعد آخر تعديل، مع مؤشر حالة ("بيتحفظ تلقائيًا... / اتحفظ")
- **Draft Recovery:** لو قفلت المتصفح بغلط قبل الحفظ، هيظهر تنبيه "فيه مسودة محفوظة، تسترجعها؟" أول ما ترجع
- **Mini Version History:** آخر 5 نسخ لكل فصل، مع زرار استرجاع فوري لأي نسخة سابقة

### 🔍 بحث واستكشاف
- **Universal Search** (⌘K / Ctrl+K) — يدور في الفصول والقوالب وأسئلة المقابلات مع بعض، والنتائج مقسّمة بالنوع

### 🛡️ شبكة أمان للمحتوى
- **Recycle Bin (سلة محذوفات):** أي حذف (فصل أو قالب) بيروح للمحذوفات بدل ما يمسح فورًا، وبيفضل 30 يوم قابل للاسترجاع قبل الحذف النهائي التلقائي
- **Activity Log:** سجل بسيط لكل حاجة اتعملت (إنشاء/تعديل/حذف/استرجاع/تسجيل دخول) بالتاريخ والوقت
- **Backup / Export / Import:** زرار واحد يصدّر كل بيانات الموقع (فصول، قوالب، أسئلة، إعدادات) كملف JSON، وزرار لاستعادتها بالكامل وقت الحاجة

### 🖼️ رفع صور بسيط (Hero + Preview فقط)
- صورتك الشخصية ومعاينات القوالب بقى ممكن ترفعها كملف مباشرة من الأدمن (بدل ما تحتاج رابط خارجي دايمًا)
- **قرار تقني مهم:** الصور بتتخزن base64 جوه قاعدة البيانات نفسها، مش كملفات على السيرفر — لأن أغلب الاستضافات المجانية اللي بتشتغل بـ Docker (زي Back4app أو Render) قرصها مؤقت (بيتصفّر مع كل نشر جديد)، فالملفات المحلية كانت هتختفي بمرور الوقت. الحل ده مضمون ومجاني بالكامل، ومناسب تمامًا لعدد الصور المحدود اللي هيستخدمه الموقع (حد أقصى 800KB للصورة).

### ✅ SEO Checklist
- تبويب SEO في كل فصل وقالب بقى فيه قايمة تفقّد بصرية (✅/❌) توضح إيه اللي اتظبط وإيه الناقص، قبل ما تنشر

## 🐛 ملاحظة عن جودة الاختبار

كل ميزة في الجولة دي اتفحصت فعليًا مش بس بالبناء (Build): شغّلت السيرفر الحقيقي واختبرت الـ Rate Limiting بمحاولات دخول فعلية (5 مسموح، السادسة اتمنعت)، والبحث الشامل، والـ Security Headers. مفيش حاجة "افترضت إنها شغالة" من غير تجربة فعلية.

**اكتشاف مهم أثناء تجهيز Dockerfile:** حاكيت بالظبط اللي Back4app/أي استضافة Docker هتعمله (تثبيت بدون devDependencies)، ولقيت السيرفر بيقع فورًا بسبب استيراد غير مباشر لأدوات التطوير (Vite) جوه كود الإنتاج. صلحتها بفصل كود التطوير تمامًا عن كود الإنتاج، وأعدت الاختبار بنفس الطريقة (تثبيت إنتاج فقط + تشغيل فعلي) للتأكد إن المشكلة اتحلت 100%. لولا المحاكاة دي، الموقع كان هيقع لحظة أول نشر فعلي.
